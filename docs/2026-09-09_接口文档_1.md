# 前端整改说明：选集卡片 `resource_bundle`（v1.4）

> 文档版本：**v1.4**  
> 日期：**2026-09-09**  
> 给谁看：前端同学（这一份即可落地，不必再翻旧文档）  
> 接口路径不变：`POST /api/v1/chat/stream`（SSE）  
> 字段命名：全部 **snake_case**

---

## 0. 一句话

检索成功后，**播放地址不再出现在助手气泡文字里**。  
后端会多推一块 `type: "resource_bundle"` 的结构化 JSON。前端用它渲染「线路 Tab + 选集方块 + 页内播放器」，不要再把 URL 当纯文本拼进气泡。

旧的扁平 `video` / `link` / `image` 块仍会下发（兼容）。**同一轮里如果已经收到 `resource_bundle`，请忽略同轮的 `video`，避免重复卡片。**

---

## 1. 为什么要改

旧行为（必须干掉）大致长这样，全部塞在 `text_delta` 里：

```
插件: SiliSili
关键词: 鬼灭之刃
视频资源（35）:
- 第01集 => https://....m3u8
- 第01集 => https://....m3u8.php?...
- 第01集 => https://....mp4?X-Amz-Signature=...
```

问题：同一集在多条 CDN 上重复、签名直链又臭又长、无法点选播放。

新分工：

| 角色 | 职责 |
|------|------|
| 大模型 `text_delta` | 只说 2～3 句人话，例如「为你找到了《鬼灭之刃》，共 3 条线路，建议走高速直链。」**禁止出现 URL** |
| SSE `resource_bundle` | 线路 + 集数 + 真实播放地址 |
| 前端 | 腾讯视频 / B 站那种折叠选集面板；点击集数用播放器打开 |

## 2. 请求侧：不用改

```http
POST /api/v1/chat/stream
Content-Type: application/json
Accept: text/event-stream
```

```json
{
  "conversation_id": "conv_xxx",
  "message": "帮我找《鬼灭之刃》的播放资源",
  "need_title": true
}
```

会话、附件上传、`need_title` / `done.title` 规则与之前完全相同。  
超时建议 **≥ 120s**（识图 + 爬虫可能较慢）。流式期间禁用重复发送。

---

## 3. SSE 帧格式（没变）

每帧空行分隔，先看 `event:`，再解析 `data:` 里的 `type`。  
**不要把所有 `chunk` 都当成文字。**

```
event: chunk
data: {"type":"resource_bundle", ...}

event: chunk
data: {"type":"text_delta","content":"为你找到了《鬼灭之刃》……"}

event: chunk
data: {"type":"video", ...}          ← 兼容块，有 bundle 时可丢弃

event: chunk
data: {"type":"link", ...}

event: chunk
data: {"type":"image", ...}

event: done
data: {"type":"done","message_id":"msg_xxx","conversation_id":"conv_xxx","title":"鬼灭之刃播放资源"}
```

### 3.1 到达顺序（重要）

`resource_bundle` **经常先于** `text_delta` 到达（工具先跑完，模型后说话）。  
UI 不要假设「先有正文再有卡片」。卡片可以先出现，推荐语随后追加。

### 3.2 块类型

| `data.type` | `event` | 前端动作 |
|-------------|---------|----------|
| `resource_bundle` | `chunk` | **主渲染**：线路 Tab + 选集方块 |
| `text_delta` | `chunk` | 拼到助手气泡正文，不要从中解析 URL |
| `video` | `chunk` | 仅当本轮 **没有** `resource_bundle` 时，画旧版单集卡片 |
| `link` | `chunk` | 详情/外链列表（不是播放直链） |
| `image` | `chunk` | 海报缩略图（爬虫封面，不是用户上传图） |
| `done` | `done` | 结束流；缓存 `conversation_id`；若有 `title` 写入侧边栏 |
| `error` | `error` | Toast + 结束流，保留已渲染内容 |

## 4. `resource_bundle` 字段

```json
{
  "type": "resource_bundle",
  "anime_title": "鬼灭之刃",
  "plugin_name": "SiliSili",
  "current_episodes_count": 5,
  "sources": [
    {
      "source_name": "高速直链 (R2)",
      "kind": "mp4",
      "recommended": true,
      "episodes": [
        {
          "title": "第01集",
          "url": "https://cdn.example.com/ep1.mp4",
          "format": "mp4"
        },
        {
          "title": "第02集",
          "url": "https://cdn.example.com/ep2.mp4",
          "format": "mp4"
        }
      ]
    },
    {
      "source_name": "非凡云播 (m3u8)",
      "kind": "hls",
      "recommended": false,
      "episodes": [
        {
          "title": "第01集",
          "url": "https://cdn.example.com/ep1/index.m3u8",
          "format": "m3u8"
        }
      ]
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | `"resource_bundle"` | ✅ | 固定值 |
| `anime_title` | `string` | ✅ | 作品名，卡片标题 |
| `plugin_name` | `string` | ❌ | 来源插件，可做角标 |
| `current_episodes_count` | `number` | ✅ | 去重后的集数（不是 URL 条数） |
| `sources` | `Source[]` | ✅ | 播放线路，**至少 1 条**（有资源时才会发这块） |
| `sources[].source_name` | `string` | ✅ | Tab 文案，如 `高速直链 (R2)` |
| `sources[].kind` | `"mp4"` \| `"hls"` \| `"unknown"` | ✅ | 线路介质，决定默认播放器策略 |
| `sources[].recommended` | `boolean` | ✅ | 默认选中这一条；同一 bundle 里通常只有一条为 `true` |
| `sources[].episodes` | `Episode[]` | ✅ | 已按集数排序、线路内标题去重 |
| `episodes[].title` | `string` | ✅ | `第01集` / `第1集` 等，不要改写 |
| `episodes[].url` | `string` | ✅ | 播放地址，**只给播放器 / 复制按钮，不要渲染进气泡** |
| `episodes[].format` | `"m3u8"` \| `"mp4"` \| `"unknown"` | ✅ | 单集格式；`m3u8` 必须走 HLS |

常见线路名（后端归纳，前端按字符串展示即可，不要写死匹配）：

- `高速直链 (R2)` — 直链 mp4，优先推荐  
- `Sili 专属源` — 站点自己的 m3u8  
- `非凡云播 (m3u8)` — 第三方 HLS  
- `樱花动漫` / 插件 `线路1` `线路2`

## 5. 推荐 UI（对标腾讯视频 / B 站）

```
┌─────────────────────────────────────────────┐
│ 鬼灭之刃          更新至 5 集    SiliSili   │
│                                             │
│ [高速直链 (R2) ★推荐]  [非凡云播]  [Sili]   │
│                                             │
│  [01] [02] [03] [04] [05]                   │
│                                             │
│  当前：第01集     [播放]  [复制链接]         │
└─────────────────────────────────────────────┘
```

### 必须做

1. **线路 Tab**：`sources` 从左到右；`recommended === true` 的默认选中，Tab 上加「推荐」。  
2. **选集方块**：当前线路的 `episodes`；展示序号（从 `title` 里取数字，取不到就用原 `title`）。  
3. **点击集数 → 页内播放**，不要 `window.open` 把用户踢走。  
   - `format === "mp4"` 或 `kind === "mp4"`：普通 `<video>` / ArtPlayer / DPlayer  
   - `format === "m3u8"` 或 `kind === "hls"`：必须 HLS（hls.js，或 Safari 原生）  
4. **复制链接**：`navigator.clipboard.writeText(episode.url)`，成功给 Toast。  
5. 助手气泡只渲染 `text_delta` 的推荐语，**不要**把 `url` 印成可点 Markdown。

### 建议做

- 播放器用弹层 / 抽屉，支持切集（同一线路上下集）。  
- 切换 Tab 时保持「当前集数」：若新线路也有同名 `title`，停在同一集。  
- 移动端：Tab 可横滑，选集网格 6～8 列。  
- 播放失败：提示「该线路暂时无法播放，请换一条」；R2 直链带 `X-Amz-Expires`，大约 **1 小时内有效**，过期需要用户重新检索（当前没有单独的刷新播放地址接口）。

### 不要做

- 不要把 `resource_bundle` 当文字 `JSON.stringify` 进气泡。  
- 不要在已有 bundle 时再为每条 `video` 画一张「第01集」卡片。  
- 不要截断 URL 的 query（签名参数丢掉就播不了）。  
- 不要把用户上传图（气泡左侧）和爬虫 `image` 封面混在一个数组。

## 6. TypeScript（直接可贴）

```typescript
export interface ChatStreamRequest {
  message: string
  conversation_id?: string
  need_title?: boolean
  attachments?: Array<{
    type?: 'image'
    image_id?: string
    image_url?: string
  }>
}

export type StreamChunk =
  | { type: 'text_delta'; content: string }
  | {
      type: 'video'
      url: string
      title: string
      format?: 'm3u8' | 'mp4' | 'unknown'
      source_page?: string
      road_name?: string
    }
  | { type: 'link'; url: string; title: string; description?: string }
  | { type: 'image'; url: string; alt?: string }
  | {
      type: 'resource_bundle'
      anime_title: string
      plugin_name?: string
      current_episodes_count: number
      sources: PlaybackSource[]
    }
  | { type: 'done'; message_id: string; conversation_id: string; title?: string }
  | { type: 'error'; code: string; message: string }

export interface PlaybackSource {
  source_name: string
  kind: 'mp4' | 'hls' | 'unknown'
  recommended: boolean
  episodes: PlaybackEpisode[]
}

export interface PlaybackEpisode {
  title: string
  url: string
  format: 'm3u8' | 'mp4' | 'unknown'
}

export interface AssistantMessage {
  id?: string
  role: 'assistant'
  content: string
  resourceBundle?: Extract<StreamChunk, { type: 'resource_bundle' }>
  videos: Extract<StreamChunk, { type: 'video' }>[]
  links: Extract<StreamChunk, { type: 'link' }>[]
  images: Extract<StreamChunk, { type: 'image' }>[]
  streaming: boolean
}
```

### 消费伪代码

```typescript
function applyChunk(message: AssistantMessage, chunk: StreamChunk) {
  switch (chunk.type) {
    case 'text_delta':
      message.content += chunk.content
      break
    case 'resource_bundle':
      message.resourceBundle = chunk
      message.videos = [] // 避免旧卡片残留
      break
    case 'video':
      if (!message.resourceBundle) message.videos.push(chunk)
      break
    case 'link':
      message.links.push(chunk)
      break
    case 'image':
      message.images.push(chunk)
      break
    case 'done':
      message.id = chunk.message_id
      message.streaming = false
      break
    case 'error':
      showError(chunk.code, chunk.message)
      message.streaming = false
      break
  }
}
```

解析 SSE 时按空行分帧，读 `event:` + `data:`。`done` 后把 `conversation_id` 写回 store。

## 7. 联调怎么验

```bash
curl -N -X POST http://localhost:8000/api/v1/chat/stream \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{"message":"帮我找《葬送的芙莉莲》的播放资源","need_title":true}'
```

**过关标准：**

- [ ] 出现 `"type":"resource_bundle"`，且 `sources` 为数组  
- [ ] 助手正文 **没有** `- 第01集 => https://`  
- [ ] 页面出现线路 Tab，默认选中 `recommended: true`  
- [ ] 点【01】能在页内出声/出画（mp4 直链或 m3u8 HLS）  
- [ ] 复制链接能贴出完整 URL（含 query）  
- [ ] 有 bundle 时不再刷一排重复「第01集」小卡片  
- [ ] 最后有 `event: done`；首轮若带了 `need_title` 则 `done` 含 `title`  
- [ ] 无资源时只有短文字或 `error`，不要空卡片

未配 `DEEPSEEK_API_KEY` 时后端走启发式检索，同样会推 `resource_bundle`（若爬到了资源）。  
`VITE_USE_MOCK_STREAM` 必须为 `false`，否则联不到真实块。
