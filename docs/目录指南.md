# 目录指南

给面试现场翻代码用。包名就是职责边界；协议细节见 [接口文档](接口文档.md)，启动与三条主路径见 [联调指南](联调指南.md)。

根包：`src/main/java/com/agentcrawler/`。站点规则 JSON 在 `src/main/resources/plugins/`。

## 一次请求先看哪几个文件

```
POST /api/v1/chat/stream
  ChatController          写出 SSE，并逐帧 flush
    ChatService           锚定会话，交给 AgentHandler
      LangChainStreamingAgent
        有 Key → AnimeAgent.chat（意图在系统提示里）
        无 Key → CrawlIntentParser（只认书名号）
        工具回调里从 CrawlResultBuffer 取全量结果，经 StreamEmitter 推卡片
          ResourceCrawlTools.searchResources
            ResourceCrawlerService.crawl
              CrawlSingleflight → 短 TTL 播放缓存 → COS 对象缓存
              → SiteCircuitBoard 门禁 → RuleEngine / SiteFallback
```

播放 URL 不进模型上下文：工具返回值只有线路和集数摘要，卡片走 SSE `resource_bundle`。

## 包 → 职责

| 包 | 职责 | 先看的类 |
|----|------|----------|
| `api` | HTTP 入口：对话流、会话、上传、被动刷新 | `ChatController` |
| `service` | 会话编排，不碰站点 HTML | `ChatService` |
| `agent` | Agent 入口接口，和 LangChain 解耦 | `AgentHandler` |
| `agent/langchain` | 意图、工具、Token 门禁、结果双通道 | `AnimeAgent`、`LangChainStreamingAgent`、`ResourceCrawlTools`、`AgentTokenGate` |
| `agent/session` | 多轮作品锚定。换题清空，检索成功后写回作品名 | `SessionBlackboardService`、`SessionContextTools` |
| `crawler/service` | 一次检索的顺序：单飞、缓存、熔断、插件、降级 | `ResourceCrawlerService` |
| `crawler/engine` | Kazumi 风格规则：搜索、章节、播放页 | `RuleEngine`、`XPathRuleStrategy`、`ApiRuleStrategy` |
| `crawler/plugin` | 启动时加载 `plugins/*.json` | `PluginRegistry` |
| `crawler/model` | 规则与检索结果的数据结构 | `PluginRule`、`CrawlResourceResult` |
| `crawler/http` | 站点 OkHttp。和链接嗅探的客户端分开，避免 SSRF 策略混用 | `SiteHttpClient` |
| `crawler/webview` | `useWebview` 站点用 Playwright 截 `.m3u8` / `.mp4`，全局最多 2 路 | `PlaywrightWebViewFetcher` |
| `crawler/media` | 从 HTML / 网络响应里抽媒体地址 | `MediaExtractor` |
| `crawler/fallback` | 插件拿不到播放地址时的专用适配（YHDM、SiliSili） | `SiteFallback` |
| `crawler/reliability` | 单飞、按源熔断、失败分类、后台 canary | `CrawlSingleflight`、`SiteCircuitBoard` |
| `crawler/cache` | 检索出口的短 TTL 播放缓存和长 TTL 目录快照（本地 / Redis KV） | `TieredCrawlerResultCache` |
| `cache` | COS 对象正文 + Redis LRU 热索引。和上面的短 TTL 缓存不是一层 | `CosObjectBlobStore`、`RedisCrawlHotIndex` |
| `streaming` | SSE 帧编码、思考进度、停止生成 | `SseEncoder`、`StreamEmitter`、`GenerationRuns` |
| `link` | 用户粘贴的 URL / magnet：提取、分类、SSRF、嗅探。不爬选集 | `LinkInspectorService` |
| `vision` | 识图。主 Agent 只传 URL，不碰 base64 | `ImageUploadService`、`DeepSeekVisionClient` |
| `store` | 会话 meta 与 ChatMemory，可选 Redis | `PersistentConversationStore` |
| `config` | Bean 装配。Agent、工具、COS、熔断参数都在这里决定要不要创建 | `LlmConfig`、`CosCacheConfig` |
| `core` | 错误码与异常 | `AppException`、`ErrorCode` |
| `model` | 请求 / 响应 DTO | `ChatStreamRequest` |

两层缓存不要混：

- `crawler/cache`：同一次检索的播放结果，短 TTL（签名直链会过期），目录快照更长。
- `cache`：成功结果落到 COS，不按硬 TTL 删；Redis 只存目录、大小和最近访问时间，用来做容量淘汰。

## 面试快速定位

| 主题 | 打开 | 为什么在这 |
|------|------|------------|
| 意图识别 / Agent | `agent/langchain/AnimeAgent.java` | 意图写在 `@SystemMessage`：找番必须调 `searchResources`，闲聊禁止调工具。模型自己做分类。 |
| 无 Key 时的意图 | `agent/langchain/CrawlIntentParser.java` | 正则只认《书名号》和「找/搜」。`LangChainStreamingAgent.streamReply` 在 Agent Bean 缺失时走这里，链路仍能联调。 |
| Agent 入口 | `agent/langchain/LangChainStreamingAgent.java` | `streamWithAgent` 串起黑板、链接前置解析、工具循环和 SSE。`onToolExecuted` 才把卡片推出去。 |
| Tool 注册 | `config/LlmConfig.java` 的 `animeAgent` | `AiServices.builder(...).tools(...)` 把带 `@Tool` 的 Bean 交给 LangChain4j。识图工具可选，缺了不影响检索。 |
| Tool 实现 | `agent/langchain/ResourceCrawlTools.java` | `searchResources` 调爬虫。返回给模型的是摘要；全量结果先放进 `CrawlResultBuffer`。 |
| 其它工具 | `LinkInspectorTool`、`AnimeVisionTool`、`agent/session/SessionContextTools` | 补解析一条 URL、识图、锁定或清空作品黑板。都在 `LlmConfig` 里一起注册。 |
| 规则引擎 | `crawler/engine/RuleEngine.java` | 按 `PluginRule` 拉搜索页和章节页。`useWebview` 走 Playwright，失败回退 OkHttp。 |
| 规则从哪来 | `crawler/plugin/PluginRegistry.java` | 读 `classpath:plugins/*.json`。用单独的 camelCase ObjectMapper，避免和 HTTP 的 SNAKE_CASE 绑错字段。 |
| 主检索编排 | `crawler/service/ResourceCrawlerService.java` | `crawl` 是入口；`crawlUncoalesced` 里才是「插件失败再降级」。 |
| SSE | `api/ChatController.java`、`streaming/SseEncoder.java`、`streaming/StreamEmitter.java` | Controller 用 `StreamingResponseBody` 逐帧 flush，并关掉反向代理缓冲。帧类型只有 `chunk` / `done` / `error`，卡片种类看 JSON 里的 `type`。 |
| AgentTokenGate | `agent/langchain/AgentTokenGate.java` | 工具调用前的 token 是「我来检索」这类旁白。工具边界丢掉，流结束时剩下的才是推荐语。调用点在 `LangChainStreamingAgent` 的 `onNext` / `onToolExecuted` / `onComplete`。 |
| Singleflight | `crawler/reliability/CrawlSingleflight.java` | 同一 `site + keyword` 只爬一次，等待者共享这次结果。调用结束就摘掉 map 项，所以它不是缓存。包在 `ResourceCrawlerService.crawl` 最外层，缓存查找也在里面，避免击穿。 |
| Redis 热索引 | `cache/RedisCrawlHotIndex.java` | Hash `acrawl:cos:dir` 存目录和大小，ZSet `acrawl:cos:lru` 的分数是最近访问时间。命中用一条 Lua 读目录并节流 `ZADD`，避免每次请求都改分数。淘汰在 `CrawlCacheEvictor`，不走用户请求。 |
| 熔断 | `crawler/reliability/SiteCircuitBoard.java` | **自研状态机，仓库里没有 Resilience4j。** 用户路径在 OPEN 时直接跳过，不做半开试探；半开会把失败延迟加到这次检索上。恢复只走 `UpstreamProbeScheduler` 的后台 canary。空目录不算失败，见 `UpstreamFailureClassifier`。门禁调用在 `ResourceCrawlerService.crawlPlugins`。 |
| COS | `cache/CosObjectBlobStore.java`、`config/CosCacheConfig.java` | 对象正文在腾讯云 COS。`CosCacheConfig` 在配齐密钥后创建客户端；开了 Redis 就把 `RedisCrawlHotIndex` 交给 `BlobCrawlResultCache`。COS 上的 `cache/v1/index.json` 是热索引备份，Redis 空了靠它重建。404 当缓存未命中，方便和淘汰并发。 |
