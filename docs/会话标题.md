# 会话标题

> 文档版本：v1.3  
> 适用范围：本后端 ↔ 前端  
> 关联文档：[接口文档](接口文档.md)

---

## 1. 背景

前端已实现 **多会话管理**，会话列表、消息内容、当前会话均保存在浏览器 IndexedDB，**后端无需存储历史对话正文**。

后端只需在 **每个会话的第一轮回复结束时** 给一个短标题，供左侧历史列表展示（类似网页版 ChatGPT）。后续轮次不要再改标题。

---

## 2. 请求扩展：`need_title`

`POST /api/v1/chat/stream` 请求体增加可选字段：

```json
{
  "conversation_id": "conv_xxx",
  "message": "帮我找《葬送的芙莉莲》的播放资源",
  "need_title": true
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `need_title` | `boolean` | ❌ | 仅该会话 **第一条用户消息** 为 `true`；之后不要带，或显式 `false` |

前端行为：

- 新会话默认标题为「新对话」
- 用户发出第一条消息后，本地先用首句做临时标题
- 该次请求带 `need_title: true`
- 收到 `done.title` 后替换为后端概述，并锁定，不再请求标题

---

## 3. 响应扩展：`done.title`

SSE `done` 事件在 `need_title=true` 时 **建议** 带上 `title`：

```
event: done
data: {"type":"done","message_id":"msg_xxx","conversation_id":"conv_xxx","title":"葬送的芙莉莲播放资源"}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `title` | `string` | 条件 | 仅首轮需要。12～24 个汉字为宜，不要换行 |

后续轮次 `done` **不要**再返回 `title`（即使返回，前端也会忽略）。

### 标题生成建议

用用户第一句 + 可选识图结果，压成短语，例如：

- 「帮我找《葬送的芙莉莲》的播放资源」→ `葬送的芙莉莲播放资源`
- 仅图片 → `图片识图`

若暂时无法生成，可省略 `title`。前端会继续用本地临时标题，不影响对话。

## 4. 前端已自行完成（无需后端）

| 能力 | 实现 |
|------|------|
| 多会话列表 | 对话框左侧，当前会话置顶 |
| 排序 | 当前会话置顶 → 其余按最后一次开始对话（发出用户消息）的时间新→旧 |
| 切换 / 删除 | IndexedDB |
| 消息持久化 | IndexedDB |
| `conversation_id` | 仍用现有 `done.conversation_id`，每条会话独立 |

后端 **不必** 提供会话列表、删除、历史消息查询接口。
