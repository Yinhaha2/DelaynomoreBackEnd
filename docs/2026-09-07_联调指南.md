## 1. 联调前准备

### 1.1 后端启动

```bash
cd bullshitbackend
cp .env.example .env          # 填入 DEEPSEEK_API_KEY，切勿提交
export $(grep -v '^#' .env | xargs)
mvn spring-boot:run
```

默认：`http://localhost:8000`

探活：

```bash
curl -s http://localhost:8000/health
# {"status":"ok"}
```

| 环境变量 | 必填 | 说明 |
|----------|------|------|
| `DEEPSEEK_API_KEY` | **是**（完整 Agent / 识图） | 未配置时降级为启发式文本检索，**无多轮、无 Vision** |
| `DEEPSEEK_BASE_URL` | 否 | 默认 `https://api.deepseek.com/v1` |
| `DEEPSEEK_MODEL` | 否 | 默认 `deepseek-chat` |
| `DEEPSEEK_VISION_MODEL` | 否 | 默认 `deepseek-v4-flash-vision-exp` |
| `AGENT_PUBLIC_BASE_URL` | 识图联调建议设 | 默认 `http://localhost:8000`；前端预览图用这个拼 URL |
| `AGENT_UPLOAD_DIR` | 否 | 默认 `./data/uploads` |

### 1.2 前端启动

```env
VITE_USE_MOCK_STREAM=false
VITE_API_BASE_URL=
```

- **必须关 Mock**，否则看不到 `video` / `link` / `image`，也测不了上传和识图。
- Vite 把 `/api` 代理到 `http://localhost:8000`。
- 后端 CORS 已放行 `http://localhost:5173` 与 `http://127.0.0.1:5173`。

### 1.3 联调约定

| 项 | 约定 |
|----|------|
| JSON 字段 | **snake_case**（`conversation_id`、`image_url`） |
| 流式接口 | `Accept: text/event-stream`，否则 HTTP **406** |
| 超时 | 识图 + 检索可能较慢，前端超时建议 **≥ 120s** |
| 会话 | 全程同一 `conversation_id`，内存存储，**后端重启即丢失** |

## 2. 接口一览

| 方法 | 路径 | 用途 |
|------|------|------|
| `GET` | `/health` | 探活 |
| `POST` | `/api/v1/conversations` | 创建会话（可选） |
| `POST` | `/api/v1/chat/stream` | 发消息，SSE 流式回复 |
| `POST` | `/api/v1/uploads/images` | 上传用户图片（multipart `file`） |
| `GET` | `/api/v1/files/images/{image_id}` | 预览已上传图片 |

**前端不用单独调「识图接口」或「解析链接接口」。**

- 图片：先上传，再把 `image_id` 放进 `attachments` 发对话。
- 链接：直接写在 `message` 文本里，后端自动提取。

---

## 3. SSE 消费规则（三条路径共用）

每帧：

```
event: chunk
data: {"type":"text_delta","content":"..."}

event: done
data: {"type":"done","message_id":"msg_xxx","conversation_id":"conv_xxx"}
```

| `data.type` | SSE event | 前端动作 |
|-------------|-----------|----------|
| `text_delta` | `chunk` | 拼到助手正文（**不含裸播放 URL**） |
| `resource_bundle` | `chunk` | **v1.4** 按线路分组的选集卡片（Tab + 集数方块） |
| `video` | `chunk` | 兼容扁平播放卡片；已处理 `resource_bundle` 时可忽略 |
| `link` | `chunk` | 推进 `links[]`，可点击列表 |
| `image` | `chunk` | 推进 `images[]`（**爬虫封面，不是用户上传图**） |
| `done` | `done` | 结束流，保存 `message_id` / `conversation_id`；若带 `title` 则写入侧边栏标题 |
| `error` | `error` | Toast + 结束流 |

### 3.1 首轮会话标题（v1.3）

新会话第一条用户消息请带 `need_title: true`。后端在 `done` 中返回短标题（约 12～24 字），例如「葬送的芙莉莲播放资源」。仅图片时为「图片识图」。后续轮次不要带该字段，`done` 也不再含 `title`。

协议详见 `2026-09-07_接口文档_2.md`。后端**不存**历史正文，会话列表由前端 IndexedDB 负责。

不要把所有 `chunk` 都当 `text_delta`。收到 `done.conversation_id` 后务必缓存，后续轮次带上。

## 4. 三条主路径（按这个顺序联调）

### 路径 A：纯文本搜资源（先打通 SSE）

**目的**：确认代理、SSE 解析、资源卡片都通。

```bash
# 1) 建会话（也可省略，stream 会自动建）
curl -s -X POST http://localhost:8000/api/v1/conversations \
  -H "Content-Type: application/json"

# 2) 流式对话
curl -N -X POST http://localhost:8000/api/v1/chat/stream \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{
    "conversation_id": "conv_替换成上一步的ID",
    "message": "帮我找《葬送的芙莉莲》的播放资源"
  }'
```

**期望：**

- 出现短 `text_delta`（观影推荐或启发式「正在检索」），**不应**出现 `- 第01集 => https://...` 这种裸链列表
- 出现 `resource_bundle`（按线路分组的选集）
- 可能出现兼容用的 `video` / `link` / `image`
- 最后 `event: done`
- 前端：助手气泡有推荐语；选集 Tab + 集数方块；不要把 `video` 再画成重复卡片

**第二轮（同一会话，测记忆）：**

```json
{
  "conversation_id": "conv_xxx",
  "message": "它的第二季有吗？"
}
```

不要新建 `conversation_id`，否则黑板和 ChatMemory 对不上。

---

### 路径 B：发图识图 + 搜资源

**目的**：上传 → 附件对话 → Vision Tool → 黑板锁定 → 爬虫。

```bash
# 1) 上传（字段名必须是 file）
curl -s -X POST http://localhost:8000/api/v1/uploads/images \
  -F "file=@./meme.png"

# 响应示例
# {"image_id":"img_xxx","image_url":"http://localhost:8000/api/v1/files/images/img_xxx","mime_type":"image/png","size":102400}

# 2) 预览（浏览器或 img src 即可）
curl -I http://localhost:8000/api/v1/files/images/img_xxx

# 3) 带图对话
curl -N -X POST http://localhost:8000/api/v1/chat/stream \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{
    "conversation_id": "conv_xxx",
    "message": "这张表情包出自哪一集？",
    "attachments": [{"type":"image","image_id":"img_xxx"}]
  }'
```

也可用 `image_url` 代替 `image_id`。`message` 可为空（仅有 attachments 时后端会补默认文案）。

**前端必须：**

1. 选图 → `FormData.append('file', file)` → `POST /api/v1/uploads/images`
2. 用户气泡展示本地预览或 `image_url`
3. `chat/stream` 带 `attachments`，**不要把 base64 塞进 `message`**
4. 流式期间禁用发送，超时 ≥ 120s

**期望：** 助手先描述识别结果，再可能吐出资源块。后续只发文字追问即可，例如「那这一集最后打赢了吗？」。

**限制：** JPEG / PNG / GIF / WebP，单文件 ≤ 32MB。

---

### 路径 C：消息里贴链接（无需新接口）

**目的**：后端从 `message` 文本里提取 URL / magnet，嗅探标题后锁定作品。

```bash
curl -N -X POST http://localhost:8000/api/v1/chat/stream \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{
    "conversation_id": "conv_xxx",
    "message": "帮我看看这个 https://bangumi.tv/subject/328609 讲的啥，有没有在线看"
  }'
```

磁力链同样直接贴在句子里：

```json
{
  "conversation_id": "conv_xxx",
  "message": "这个 magnet:?xt=urn:btih:abc123&dn=芙莉莲 能放吗"
}
```

**前端必须：** 原样发送用户输入，**不要截断 query**（`?`、`&`、`#`），不要把链接拆成附件。

**期望：** 助手基于页面标题 / 作品名回答，需要资源时仍走 SSE `video`/`link`/`image`。短链（如 `https://b23.tv/...`）由后端跟随跳转，前端不用先展开。

## 5. 前端最小实现清单

### 5.1 类型

```typescript
export interface ChatStreamRequest {
  message: string
  conversation_id?: string
  attachments?: Array<{
    type?: 'image'
    image_id?: string
    image_url?: string
  }>
}

export type StreamChunk =
  | { type: 'text_delta'; content: string }
  | {
      type: 'video'
      url: string
      title: string
      format?: 'm3u8' | 'mp4' | 'unknown'
      source_page?: string
      road_name?: string
    }
  | { type: 'link'; url: string; title: string; description?: string }
  | {
      type: 'image'
      url: string
      alt?: string
    }
  | {
      type: 'resource_bundle'
      anime_title: string
      plugin_name?: string
      current_episodes_count: number
      sources: Array<{
        source_name: string
        kind: 'mp4' | 'hls' | 'unknown'
        recommended: boolean
        episodes: Array<{ title: string; url: string; format: 'm3u8' | 'mp4' | 'unknown' }>
      }>
    }
  | { type: 'done'; message_id: string; conversation_id: string }
  | { type: 'error'; code: string; message: string }
```

### 5.2 发送示例

```typescript
const res = await fetch('/api/v1/chat/stream', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Accept: 'text/event-stream',
  },
  body: JSON.stringify({
    conversation_id: conversationId,
    message,
    attachments,
  }),
})
```

解析时按空行分帧，读 `event:` + `data:`。`done` 后把 `conversation_id` 写回 store。

### 5.3 用户图 vs 爬虫图

| 来源 | 怎么来 | 渲染位置 |
|------|--------|----------|
| 用户上传 | `POST /uploads/images` | **用户气泡** 缩略图 |
| 爬虫封面 | SSE `type: "image"` | **助手回复区** 资源图 |

## 6. 错误码对照

### HTTP 层（上传等 JSON 接口）

```json
{ "code": "UPLOAD_FAILED", "message": "仅支持 JPEG/PNG/GIF/WebP 图片" }
```

| HTTP | code | 场景 |
|------|------|------|
| 400 | `INVALID_REQUEST` | 空文件 / 会话不存在 |
| 406 | — | `chat/stream` 未带 `Accept: text/event-stream` |
| 500 | `UPLOAD_FAILED` | 格式/大小/落盘失败 |

### SSE `error` 事件

| code | 前端建议 |
|------|----------|
| `INVALID_REQUEST` | message 与 attachments 都空 |
| `CONVERSATION_NOT_FOUND` | 清掉旧 ID，重新 `POST /conversations` |
| `AGENT_TIMEOUT` | 提示重试（>120s） |
| `AGENT_ERROR` | 通用失败 |
| `CRAWL_FAILED` | 保留已有文字，换关键词 |
| `VISION_FAILED` | 换更清晰的图 |

## 7. 常见坑

| 现象 | 原因 | 处理 |
|------|------|------|
| 只有文字，没有 video/link/image | Mock 没关，或 SSE 把所有 chunk 当 text | `VITE_USE_MOCK_STREAM=false`；按 `data.type` 分支 |
| 助手气泡里刷满裸 m3u8/mp4 URL | 前端把 `resource_bundle`/`video` 当 `text_delta` 拼进去 | 按 `data.type` 分支；选集走卡片组件 |
| `406` | 没传 `Accept: text/event-stream` | 补请求头 |
| 识图不走 / 只会启发式搜《番名》 | 没配 `DEEPSEEK_API_KEY` | 后端环境变量 |
| 第二轮「忘了是哪部番」 | 换了 `conversation_id` 或重启过后端 | 同一 ID；内存会话重启会丢 |
| 图片预览 404 | `image_id` 错或后端重启清了磁盘索引（元数据在内存） | 重新上传 |
| 发图无识别 | 把 base64 写进 message | 走上传 + `attachments` |
| 链接识别不准 / 被截断 | 前端 encode 或截掉 query | 原文原样进 `message` |
| 贴了内网/localhost 链接没解析 | 后端默认拦截 SSRF | 用公网 URL |
| CORS | 前端不是 5173 | 后端目前只放行 Vite 默认端口 |
| m3u8 播不了 | 需要 HLS | hls.js，或降级打开 `source_page` |
| 流一直转圈 | 识图+爬虫慢，或等不到 `done` | 120s 超时；必须处理 `error`/`done` |

## 8. 联调验收 Checklist

**后端**

- [ ] `GET /health` 为 ok
- [ ] 已 export `DEEPSEEK_API_KEY`
- [ ] `POST /conversations` 返回 `conversation_id`
- [ ] 路径 A 能收到 `done`，且资源块类型正确
- [ ] 路径 B 上传返回 `image_url`，带 attachments 的 stream 能跑完
- [ ] 路径 C 消息内 URL 不丢 query，能正常结束流

**前端**

- [ ] Mock 关闭，`/api` 代理到 8000
- [ ] 缓存 `conversation_id`，多轮复用
- [ ] SSE 分支处理 `resource_bundle` / `video` / `link` / `image` / `text_delta` / `done` / `error`
- [ ] 助手消息分区：正文 / 选集卡片 / links / images
- [ ] 选图上传 + 用户气泡预览 + `attachments`
- [ ] 流式中禁用发送；处理 `error`
- [ ] 链接随文本发送，不截断

**双方一起点一次**

1. 纯文本搜一部番，看到播放卡片  
2. 同一会话追问「第二季」  
3. 发一张截图问出处  
4. 粘贴一条 Bangumi / B 站链接问「有没有在线看」

四步都通，联调过关。

## 9. 后端内部（方便对现象，前端不用对接）

同一 `conversation_id` 上，后端会：

1. 从文本提取 URL / magnet 并嗅探（链接路径）
2. 把 `attachments` 转成图片 URL，Agent 调 `analyzeAnimeImage`（识图路径）
3. 把作品名写入会话黑板，后续轮次强制锚定，避免「粉发角色认错番」
4. 需要资源时调爬虫，SSE 推 `resource_bundle`（及兼容 `video` / `link` / `image`）；LLM 只说人话

前端只需保证：**会话 ID 稳定、图片走上传、链接走原文、SSE 按类型渲染。**
