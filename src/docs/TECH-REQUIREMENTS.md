## 3. 分模块：难度 · 接口 · 资源 · 准备

### 3.1 积分 / 悬赏 / 资料（已砍真支付）

- **难度**：状态机要严谨（冻结 → 完成结算 / 取消解冻），注意幂等。
- **接口**：沿用既有 `/api/tasks`、`/api/materials`、积分账户相关；**不要再接微信支付。**
- **资源**：MySQL、对象存储 OSS/COS、Redis（可选限流）
- **过审注意**：对外文案写「校园积分激励 / 学习资料兑换」，**禁止**「提现、人民币、赏金转账」。

### 3.2 校园地图

- **API**：`GET /api/campus/spots`、`GET /api/campus/spots/:id`、`GET /api/campus/map/tasks`
- **可选厂商**：腾讯/高德 Key（非必须；自绘可上线）
- **准备**：15～30 个校内点位表即可

### 3.3 AI 课表 + 智能推荐

- **API**：`/api/ai/schedule`、`/api/ai/schedule/today`、`/api/ai/assistant/chat`、`/api/ai/feed`、`/api/ai/feed/feedback`
- 课表数据优先用户手填；教务爬虫不推荐
- 大模型输出必须再过一遍内容安全 / 敏感词

### 3.4 Canvas 海报

- 纯前端；后端可选小程序码接口

### 3.5 明确废弃

| 废弃能力 | 原因 |
|----------|------|
| `/api/treehole/*` | 匿名 UGC，个人主体与安全审核高风险 |
| `/api/bottles/*` | 同上，已随树洞一并下线 |

## 4. 【重点】过审 · 安全 · 备案 —— 后端实现必读

> 目标：个人主体也能尽量过审。下面每一条都建议写进后端任务看板。

### 4.1 小程序备案（上线硬门槛）

1. 在微信公众平台按指引完成 **小程序备案**（个人主体可选符合个人性质的服务内容标识）。  
2. **名称 / 简介 / 服务内容** 保持一致：定位「校园学习效率工具」，勿写商城、社交平台、公司名义。  
3. 备案主体信息与小程序账号主体一致；变更主体要重新评估备案。  
4. 官方参考：  
   - https://developers.weixin.qq.com/miniprogram/product/record/record_faq.html  
   - https://developers.weixin.qq.com/miniprogram/product/record/record_review.html  

### 4.2 服务器与域名安全（审核会查「能否稳定访问」）

| 项 | 要求 |
|----|------|
| HTTPS | 业务 API 必须 HTTPS；证书有效 |
| 合法域名 | request / uploadFile / downloadFile 域名全部配进小程序后台 |
| 备案域名 | 大陆服务器域名需 ICP 备案（与小程序备案不同，别混） |
| 跨域 | 小程序无浏览器 CORS 问题，但别把测试 IP 当生产长期用 |
| 健康检查 | 提供简单 `GET /api/health`，提审期间服务勿宕机 |
| 无公网裸奔管理端 | Admin 要鉴权；勿把调试接口暴露在无鉴权路径 |

### 4.3 内容安全（有 UGC 就必须做）

即使已去掉树洞，仍有 **帖子、评论、找搭子文案、资料标题/简介、私信、AI 回复**：

1. **发布前同步检测**（推荐微信内容安全）：  
   - 文本：`security.msgSecCheck`（或新版等价接口）  
   - 图片：`mediaCheckAsync` / 图片安全接口  
2. 检测不通过 → 接口返回明确错误码，前端 Toast「含违规内容」。  
3. **落库带审核状态**：`pending / approved / rejected`（可先「机审通过即 approved」，保留人审扩展）。  
4. **举报接口**（强烈建议）：`POST /api/reports`（targetType, targetId, reason）；后台能查。  
5. 频率限制：同一用户发帖/评论/找搭子 N 次/分钟，防刷。  
6. AI 回复：模型输出再过敏感词 + 内容安全；失败则返回兜底文案，勿原样吐出。

### 4.4 账号与隐私（隐私政策要对得上代码）

| 项 | 后端注意 |
|----|----------|
| 微信登录 | 只存 openid/unionid 必要字段；勿过度采集 |
| 手机号 | 个人主体若未开通或不需要，**不要强求授权手机号** |
| 日志 | 勿把用户正文、token 打到明文公共日志 |
| 注销/退出 | 提供退出登录；有条件提供「清除本地数据」说明 |
| 隐私协议 | 前端要有真实页面；协议里写清：收集什么、用于什么、存多久 |
| 用户协议 | 写明积分不可提现、资料仅供学习交流 |

### 4.5 支付与虚拟积分（防误伤审核）

1. **禁止**接入微信支付、企业付款、银行卡提现。  
2. 数据库字段、接口名尽量用 `points`，避免 `cash`/`withdraw` 出现在对外 API。  
3. 管理端若有「调账」，必须鉴权 + 审计日志，且勿在小程序端暴露。  
4. 文案统一：积分激励，不可兑换人民币。

### 4.6 文件上传安全

1. 仅允许白名单后缀（如 pdf/doc/docx/png/jpg）。  
2. 限制大小；病毒/木马可用云厂商内容检测（可选）。  
3. 下载链接用 **短时预签名 URL**，勿永久公有读敏感文件。  
4. 上传接口必须登录态；校验 Content-Type。

### 4.7 接口安全基线（过审 + 防打穿）

| 项 | 建议 |
|----|------|
| 鉴权 | 业务接口 Bearer Token；失效返回 401 |
| 越权 | 改/删/接单必须校验资源归属或状态机 |
| 幂等 | 支付替代的「积分冻结/结算」用业务单号防重复 |
| 限流 | 登录、发帖、上传、AI 对话按 IP/用户限流 |
| HTTPS only | 禁止生产环境明文 HTTP API |
| 错误信息 | 勿返回堆栈、SQL、内部路径 |
| 环境隔离 | dev/prod 配置分离；提审连 **prod 稳定环境** |

### 4.8 提审期间后端 Checklist（打印贴墙上）

- [ ] 小程序备案已通过或按平台要求处理完毕  
- [ ] ICP + HTTPS + 合法域名配置完成  
- [ ] `USE_MOCK=false` 后主路径全通：登录→课表/地图/发帖/悬赏/兑换  
- [ ] 无「树洞/漂流瓶」接口与数据  
- [ ] 发帖/评论/找搭子/资料简介已接内容安全  
- [ ] 有举报入口或至少后台可处理违规内容的方案  
- [ ] 隐私政策 / 用户协议 URL 可打开且与实际一致  
- [ ] 测试账号写在提审备注（如需要）  
- [ ] 提审周服务监控：别在审的时候发版搞挂  
- [ ] 介绍文案不写「demo/面试/测试」，定位学习工具（见 `PERSONAL-MP-REVIEW.md`）

### 4.9 类目与产品叙事（和后端文案也有关）

- 对外：校园 **学习效率工具**（课表、地点、打卡、互助任务看板）  
- 避免：社交社区、匿名树洞、交友、跑腿交易平台、电商商城  
- 找搭子：偏「组队学习/活动报名信息」，接口与文案勿做成陌生人社交匹配引擎宣传
